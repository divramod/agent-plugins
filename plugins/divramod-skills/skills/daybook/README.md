# daybook

The farm's daybook: one Markdown file per day listing what the user does not want to forget there, open chores moving
on into the next day, with the farm's unfinished plans and its watches. `scripts/daybook.py` (stdlib) does every edit;
[SKILL.md](SKILL.md) is the skill's call table. This file is the format for readers (the halverse farm view's lookout
tower and notice board): parse it, never write it.

## Where

`<farm>/daybook/` in the farm's main checkout (a worktree's session writes the main checkout's); `<farm>/daily/` when
it holds `watches.yaml` (jobsearch, German titles); `DAYBOOK_DIR` overrides (tests). `daybook/` is kept out of git
through `<git-common-dir>/info/exclude`; the script never commits. Files: `<YYYY-MM-DD>.md` per day, `watches.yaml`,
`.daybook.lock` (transient).

## Day file

No front matter. Line 1 is `# Daybook <date> (<weekday>)`, ignored. Then `## <title>` sections, all written in this
order, also when empty:

| Role | Title (German) | At carry-over | Written by |
|---|---|---|---|
| today | `Today` (`Heute`) | open items move on | `jot`, the user |
| later | `Later` (`Demnächst`) | open items move on | `jot --later`, `move` |
| watches | `Watches` | open items move on | the script, one per active watch |
| plans | `Plans` (`Offene Pläne`) | not carried, rebuilt | the script only |
| done | `Done` (`Erledigt`) | stays in the old file | `tick` |

- **Item**: a line starting `- `; following lines indented by a space belong to it. Open `- [ ] `, ticked `- [x] `.
- **Chore**: `- [ ] <text> (since <YYYY-MM-DD>)` (German `seit`); ticked `- [x] <text> (since <date>) · done <HH:MM>`
  (German `erledigt`), under Done.
- **Watch item**: `- [ ] <title> (<every or cron>; since <date>) [watch:<id>]`; the tag links it to `watches.yaml`.
- **Plan line** (generated, no checkbox): `- wt <NN>: <slug> (<done>/<total>), next <n>: <step>` per worktree plan, then
  `- <slug> (<done>/<total>), next <n>: <step> · \`<path>\`` per unfinished plan of the main checkout.
- **Generated section**: its first line is `<!-- generated by daybook.py: do not edit -->`; other tools' generated
  sections and unknown sections are kept verbatim.
- **Numbers**: the open items of Today, Later, Watches in file order from 1 (what `show` prints and `tick` takes).
- **Carry-over**: the first command of a day builds its file from the newest earlier one; nothing is deleted.

```markdown
# Daybook 2026-10-14 (Wednesday)

## Today

- [ ] answer the farmer's Q12 (since 2026-10-13)

## Later

- [ ] rename the old shotfiles (since 2026-10-09)

## Watches

<!-- generated by daybook.py: do not edit -->
- [ ] CI of the landing is green (hourly; since 2026-10-14) [watch:ci-green]

## Plans

<!-- generated by daybook.py: do not edit -->
- wt 05: 0300-daybook (2/6), next 3: Write the skill

## Done

- [x] reply to the review (since 2026-10-13) · done 09:41
```

## watches.yaml

A mapping with one key `watches:`, a list of entries (PyYAML-readable, keys sorted):

| Key | Meaning |
|---|---|
| `id` | kebab case, unique; the item tag `[watch:<id>]` |
| `title` | the item text |
| `cron` | 5-field cron in local time (`*`, `n`, `a,b`, `a-b`, `*/n`) |
| `every`, `until` | optional, in words |
| `prompt` | what a session runs; starts `Watch <id> (<folder>/watches.yaml), read-only` |
| `active` | `true` (default) or `false`; ended watches stay as history |
| `last_run`, `last_result` | set by `watch ran`: ISO 8601 time with offset, a one-line result |

A watch is **due** when active and the newest cron time at or before now lies after `last_run` (none: due).
`daybook.py --json show` gives all of it as data: `{farm, folder, date, path, open, done, plans, watches}`.
